# Paywall Strategy

## Paywall Role

The paywall is not an interruption. It is the locked door to the product's central outcome:

**A personalized school dashboard generated from the student's profile and syllabus/manual input.**

The user should arrive at the paywall thinking:

"The app knows my situation, I chose how to add schoolwork, and now my dashboard is ready."

## Hard Paywall Decision

Use a hard paywall after onboarding and input choice.

Rules:

- No dashboard access before paywall.
- No Home, Plan, Classes, Focus, Notes, Review, Widgets, or customization before payment.
- The student can restore purchases.
- Closing the paywall, if platform policy requires a close affordance, returns to a locked state, not a usable dashboard.
- The paywall should trigger after the student has enough intent to understand the value.

## Exact Trigger

Trigger the paywall after:

1. School level selected.
2. Goal selected.
3. Struggle selected.
4. Schedule style selected.
5. Input choice selected.
6. Scan source captured or minimum manual class/date setup entered.
7. Auto-personalization summary generated.

Do not trigger the paywall before input choice. The student must know what the app is about to build.

Do not trigger after dashboard access. That gives away the paid payoff.

## Pre-Paywall Value Without Dashboard Access

Allowed pre-paywall:

- Profile summary.
- Input source confirmation.
- Count-level summary, if real: "3 classes found" or "8 dates ready to review."
- Class colors generated automatically as a non-interactive preview.
- Plain list of modules that will unlock.

Not allowed pre-paywall:

- Interactive dashboard.
- Actual Next important thing.
- Full Today list.
- Full Semester Pulse state.
- Real Forecast details.
- Class hubs.
- Focus start.
- Recommended Widgets interaction.

This resolves the reviewer tension: the student sees concrete proof that setup worked, but the dashboard remains paid.

## Paywall Positioning

### Headline

"Your school dashboard is ready."

### Subheadline

"Unlock the dashboard built from your profile and syllabus."

### Value Stack

Lead with outcomes, not internal features:

1. Know what matters next.
2. See today's classes and deadlines.
3. Spot upcoming risk before the week piles up.
4. Get a focus suggestion based on your schedule.
5. Add recommended widgets for your school week.
6. Personalize class colors and dashboard style.

### Trust Copy

Use careful, review-safe language:

- "Review uncertain syllabus items before they affect your dashboard."
- "Class colors are generated automatically and can be edited with Plus."
- "Widget recommendations include previews and add instructions."

Avoid:

- "AI knows your grades."
- "Live widgets" unless proven.
- "Apple Watch" unless real.
- "Never miss a deadline" as an absolute claim.

## What Plus Unlocks

Plus unlocks:

- Personalized Home dashboard.
- Syllabus AI output applied to the dashboard.
- Manual setup saved to dashboard.
- Next important thing.
- Today module.
- Semester Pulse.
- Upcoming risk and Plan forecast.
- Focus suggestion.
- Class dashboards.
- Review helpers for uncertain imported work.
- Recommended Widgets.
- Class color editing.
- Dashboard style.
- Adaptive local recommendations.

Plus does not unlock:

- Watch features unless real.
- A theme store.
- A complex widget editor.
- Unsupported school LMS sync.
- Grade prediction unless implemented and carefully framed.

1. Profile/result header:
   - "College"

   - "Exam anxiety"
   - "Work-heavy"

2. Readiness statement:
   - "Your dashboard will prioritize exam risk, realistic focus blocks, and deadline reminders."

3. Unlock list:
   - Dashboard
   - Semester Pulse
   - Upcoming risk

   - Recommended widgets
   - Class colors

4. Plan selector:
   - Annual default if appropriate.
   - Monthly secondary.
   - Trial only if actual App Store product supports it.

5. CTA:
   - "Unlock my dashboard"

6. Restore / terms / privacy.

## Conversion Risks

### Risk: Paywall Feels Too Early

**Mitigation:** Paywall comes after profile and input choice, not immediately on launch. Show a concrete profile summary before it.

### Risk: User Does Not Trust Syllabus AI Yet

**Mitigation:** Show source confirmation and count-level extraction proof. Use review-safe language around uncertain items.

### Risk: Plus Feels Like Cosmetics

**Mitigation:** Lead with dashboard, risk, Today, and focus. Keep class colors/customization as tangible add-ons, not the core purchase.

### Risk: App Store Review Flags Unsupported Claims

**Mitigation:** Hide Watch unless real. Describe widgets as recommendations/previews/add instructions unless native behavior is proven.

### Risk: Student Wants To Try First

**Mitigation:** The "try" is the guided setup. The paid product is dashboard access. If a trial exists, sell it at the paywall.

## Subscription Value Principles

- The subscription value is repeated decision support, not one-time import.
- The dashboard should improve as the semester changes.
- Forecast, Focus, Review, and Widgets should all point back to Home.
- Personalization must affect what the student sees and does.
- Defaults must be good enough that Plus feels premium, not required cleanup.

## App Store Guardrails

- Do not imply unlimited AI if quotas or backend limits exist.
- Do not mention Watch if it cannot be demonstrated.
- Do not mention live widgets unless real widget timelines are shipped.
- Do not claim grade prediction unless implemented and framed as planning support.
- Provide restore purchase.
- Provide terms and privacy.
- Make subscription benefits visible and specific.

## Success Metrics

Primary:

- Onboarding completion rate.
- Input choice completion rate.
- Paywall view-to-start-trial/purchase.
- Paywall restore success.
- First dashboard open after purchase.

Secondary:

- Scan source capture rate.
- Manual setup completion rate.
- First Next important thing action.
- First Focus start.
- First widget recommendation viewed.
- First class color edit.

## Final Position

Hard paywall is correct if the app is disciplined:

- Personalize before payment.
- Do not leak dashboard utility.
- Sell the generated dashboard as the outcome.
- Keep Plus benefits concrete.
- Hide anything unproven.
